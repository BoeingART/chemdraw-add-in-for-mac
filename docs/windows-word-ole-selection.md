# Windows 保存后的 Word ChemDraw 对象无法打开

2026-11-03

## 原因

两个对象的 OLE 存储都能正常读取，各自包含不同的 1528 字节 CDX 数据。Windows 复制和编辑保留了相同的 `ChemOffice Drawing` 标记，标记中的旧版本信息也没有随原生结构更新。

原双击处理将所有带插件标记的 OLE 当作唯一托管对象，随后按绘图标识定位。两个对象匹配相同标识，Word 适配器抛出 `Expected exactly one matching Word figure`。WMF 预览和原生 CDX 读取均非此次失败原因。

## 修复

- 双击和面板打开均检查绘图标识在当前文档中是否唯一；比较时忽略版本后缀。
- 重复标识或无插件标记的原生 OLE 使用当前所选对象的范围位置，交给既有原生 OLE 事务读取及验证。验证成功后，只为选中的对象分配新绘图标识。
- 已唯一定位的托管对象保留现有绘图标识，继续从 OLE 读取最新结构。再次打开沿用原编辑会话。
- Word `reference` 操作的变量改名，避免覆盖同名的 `documentPath` 函数；面板打开原生对象后仍可正常定位文档。

## 验证

针对用户提供文件的两份临时副本，以相反顺序分别打开两个对象，共完成四组实际 Word/ChemDraw 验证：面板打开、双击所用选择脚本、原生 CDX 逐字节比对、独立编辑标识、再次打开以及保存回写。每次回写均检查另一个对象的结构保持原样，ChemDraw 窗口保持打开。测试副本未保存，用户原文件保持原样。

第一份副本保留完全相同的原标记；第二份副本额外测试同一绘图标识带不同版本后缀。测试副本使用独立文档标识，允许原文件同时保持打开。

上述实际应用测试使用提交前 HEAD 中的 Swift 事务代码与本次 Word 适配器修改，避免依赖工作区其他未提交改动。双击测试执行实际选择脚本，再提交对应打开事件；鼠标事件拦截本身未在本轮重新验收。OLE 自动检查通过 48 项，修改后的事件监听器通过编译。
