# Prototype architecture

This project implements custom managed drawings with a local helper and an optional Office task-pane add-in. It does not implement native OLE objects. The installed ChemDraw remains the editor; the helper's working double-click workflow does not depend on activation of the Office panel.

1. On an explicit Office ⌘V, the Swift annotated-session event tap recognizes native ChemDraw CDX or a managed drawing on the clipboard. It captures immutable source from one pasteboard generation; preview generation runs in the background transaction. Unrelated pastes pass through. ⌘C remains the application's ordinary Copy operation.
2. Each paste receives a fresh identity. ChemDraw exports a uniquely named copy of the captured native source as PDF. When the installed executable exposes its native windowless PDF interface, the helper renders the isolated snapshot through that interface without opening a document window. Builds without it retain the AppleScript PDF save path used for ChemDraw 26 compatibility. The helper converts its paths and embedded font glyphs to SVG, closes the export copy and removes successful export files. The SVG canvas fits the painted path, glyph and picture bounds with a two-point margin. Stroke outlines, transforms and clipping contribute to the bounds; paper-white backgrounds and fully transparent objects do not enlarge it. Cropping leaves the native source and relative drawing positions intact. macOS temporary directories use physical paths so AppleScript aliases resolve the same copy. Empty drawings produce an editable white canvas. The native Swift helper stores checksum-protected source in a PNG iTXt entry inside an **invisible transparent 1×1 image**. Office strips ordinary SVG metadata but preserves this payload in the tested versions. One graphic carries its source. Word alternative text and PowerPoint shape names contain `ChemOffice Drawing:<UUID>:<source revision>`; legacy identities remain readable.
3. A managed-picture double-click resolves the original document and source. Both hosts resolve the current source revision from the retained carrier; an existing saved document can also supply its embedded SVG. Source is materialized under `work/sessions/<drawing-id>/` as native `.cdx` or `.cdxml` and opened in ChemDraw. Native activation must confirm the exact focused ChemDraw window before success. Only one editing session is supported.
4. The event tap holds the managed window's ⌘W or recognized red-button event. While committing, it suppresses further key-down and mouse-down events directed to that managed ChemDraw window.
5. ChemDraw exits its live text editor and saves with bounded clean-state checks. A separate copy of the saved revision follows the same PDF-to-SVG export path as paste. A reference PNG is rendered locally from that SVG using macOS AppKit for verification. A different target document, remaining dirty state, invalid source, or failed render aborts the transaction.
6. The original Office figure's source must still match its opening version (or the same new version from a partial retry). The adapter replaces the picture with the vector carrier, preserves its width, updates height to the new aspect ratio, updates the source revision, and leaves Office saving to the user.
7. Swift reads the open Office figure's source revision and dimensions, resolves its retained source bytes, and checks the SVG aspect ratio within 0.5%. It then closes the clean ChemDraw draft and selects the original figure through its stable document identity. Saved-file tests follow the actual OOXML image relationship, compare embedded source and rendered preview, and check saved dimensions after the user saves.

PowerPoint's initial SVG import can report square picture dimensions despite a rectangular SVG canvas. Paste and demo insertion therefore receive the native viewBox aspect ratio explicitly; they do not infer it from PowerPoint's imported picture. Update uses that same SVG ratio. Word's imported dimensions were correct in the tested version.

Failures retain the session and editable draft. They do not provide cross-application rollback or a guarantee against process crashes. A monitor restart reloads a retained session; the native helper watches its parent process so an abandoned event tap does not continue intercepting input.

A repeated double-click on the same identity reopens or reveals the retained draft without overwriting it with older embedded source. If a different figure is requested while the previous window is absent, the stale draft and session record are archived under `work/recovery` before the new edit begins. If the previous drawing is still open, it is revealed and the second edit is refused. Activation failure leaves the session resumable.

Cold opening uses NSWorkspace / Launch Services to start the installed ChemDraw with the exact document URL. An AppleScript readiness loop then waits for the matching file to appear, followed by exact-window focus confirmation. Checking whether a stale document is open first checks the running application list, so that diagnostic does not accidentally start ChemDraw.

The optional panel is served over TLS on `127.0.0.1:17524`. It exposes local status and one explicit selected-drawing action. Host validation, same-origin checks, and a runtime request token protect edit requests. The HTTP handler never accepts an arbitrary file path or source payload. Panel edit requests and native events join the same serial queue, preventing concurrent save-back operations. Microsoft Office.js loads from its official CDN; chemistry stays local. No HTTP CORS access is granted.

Installation creates a self-signed leaf certificate restricted to localhost and a private key with owner-only permissions. The separate trust launcher asks the user to approve SSL localhost trust; setup and manifest copying never silently change Keychain trust. Native Mac trust validation passed on the test Mac. The in-app browser's Chromium runtime still rejected that scoped certificate, so browser-panel compatibility must not be inferred from the native trust check alone. The manifests passed Microsoft's validator. Both applications' actual Office-hosted panels, ribbon tabs, and edit actions passed on the installed App Store builds. Accessibility labels reporting disabled developer entries were disproved by successful user activation.

`src/NativeCore.swift` constructs portable graphics, reads PNG iTXt and ZIP parts, validates CFM1/CFM2 sources with system zlib and CryptoKit, and renders previews with AppKit. `src/NativeAutomation.swift` owns application object-model calls, `office/*/adapter.applescript` owns host-specific behavior, and `src/NativeBridge.swift` serializes editing transactions. `src/NativeOfficeUI.swift` serves loopback HTTPS using Network and an in-memory Security identity; it does not import the private key into the user Keychain. `src/NativeInstaller.swift` prepares and verifies manifests, certificates and preview cache folders. No Python or third-party packages are used. Since 1.0.3, preview exchange uses `~/Library/Containers/<Office bundle>/Data/Library/Caches/ChemOffice/office-preview.svg` so each host reads within its own sandbox. Private chemistry and certificates remain in ChemOffice's work directory. Cache preparation failure aborts before Office insertion and retains the captured source or draft. `src/NativeInputPolicy.swift` ensures Office receives normal input while an Apple event may be waiting for a modal dialog; the event monitor skips further helper gestures until the transaction finishes.

Native CDX uses the `CFM2` envelope; legacy XML retains `CFM1`. Both include identity, checksum, and compressed source. CDX signature and size are checked before insertion; ChemDraw parses its chemical contents on opening. No conversion through SMILES or a substitute drawing engine is used. Old hidden-box PowerPoint fixtures remain readable; a successful update writes the portable carrier and removes their managed source box.

No keystroke text or general clipboard history is logged. Explicitly pasted chemistry is retained locally in `work/pastes` for recovery. Normal logs contain identity, document path, gestures, errors, source hashes, and focus evidence. Optional `CFM_DIAGNOSTICS=1` additionally records pointer targets and close-button hit-test coordinates; it is off by default.

`src/ChemDrawDiscovery.swift` discovers application bundles in standard application folders and Spotlight-indexed locations, sorts versions numerically, and selects the newest installation. Launching, scripting, running-application checks, and window activation use its exact application path. Each editing session retains that choice so installing a different version cannot redirect a pending save.


## Open documents and source revisions (1.0.4)

Paste and write-back operate on open Office documents. Word stores a document identity in a custom property; PowerPoint stores it in an invisible marker on the slide master. Adapters resolve that identity through Save As and window switches and require one matching document and figure. Existing sessions using full paths remain readable.

A managed figure's marker includes its drawing UUID and source revision. Portable SVGs retain the full source; the helper also keeps revision-indexed carriers in `work/figures` so an unsaved drawing can be opened after a helper restart. Live verification reads the target figure's marker and dimensions from Office, checks the source against the retained carrier, and compares proportions with the SVG canvas. Saved-file verification continues to read embedded source, preview and dimensions from OOXML in tests and when recovering a figure from an existing document.

The user controls Office saving. Paste and write-back do not send Office Save or Save As commands. ChemDraw's managed editing draft is saved before returning the updated drawing.

## Installation readiness

The native app opens a visible setup checklist after installation and on reopen. A serial background check installs/read-verifies manifests and probes each installed Office host cache; a main-thread timer observes Accessibility changes and automatically advances to helper startup. Explicit Stop Helper suspends this policy. Failed startup waits for a retry or a permission change.

The helper writes atomic `helper-status-<pid>.json` updates with its PID, monitor PID and starting/ready/failed/stopped phases. The ready phase is emitted only after the monitor installs its event tap. The app accepts health for its current child PID and enables setup completion only when folder probes, application discovery, Accessibility and monitor readiness all pass. The HTTPS panel also checks readiness before exposing editing actions.


## Configuration application and permission-preserving updates

The native app uses accessory activation and a template C outline in NSStatusBar. Its menu contains a disabled version header and four actions. The main window has three buttons and a login checkbox, with no readiness/version paragraph; Word/PowerPoint file access, Accessibility and helper readiness live in a separate setup window. Explicit installation and incomplete setup open that window. Completed launches stay in the menu bar. Reopening the app restores a hidden status item. Installation readiness still requires independent Office folder checks, Accessibility and a ready event from the keyboard/mouse monitor.

NativeUpdates queries the canonical repository’s latest stable GitHub Release asynchronously. NativeUpdateDownload validates the version-specific package asset, streams it to a private staging directory, verifies its size and integrity, and reports progress with cancellation. Only HTTPS GitHub release download hosts are accepted. The app defers installation during active editing or transactions, opens the verified package after confirmation, then exits so the installer can replace it and relaunch setup. NativeLoginItem uses SMAppService.mainApp on macOS 13 and later and a per-user RunAtLoad launch agent on macOS 12. The checkbox reflects actual registration or pending approval; merely launching the app does not register login startup.

The package preinstall script renews only this application’s `SystemPolicyAppDataDetailed` consent in the signed-in desktop user’s session, so old or denied Office-container decisions can prompt again. Accessibility and Automation consent are retained. The setup window classifies Cocoa and POSIX permission failures per Office host and offers an explicit scoped renewal through **重新授权文件访问** or **修复加载项**; the regular polling loop only verifies access. Both the add-in and preview directories require a disposable write/read-back probe. Packaging signs every build with the same certificate-bound identity, selected by the public certificate committed with the project; the private key stays in the developer login keychain. Both installer scripts read the bundle identifier and display name from the packaged application's Info.plist. The bundle identifier is `com.chemdraw_addin.mac`. The application component is nonrelocatable and installs at `/Applications/ChemDraw Add-in for Mac.app`. Postinstall removes matching legacy application bundles after the replacement is present, then opens setup in the user session. Private data and Office document identities retain their existing locations and values. Offline targets skip user-session changes.

## Save synchronization and pointer feedback

The helper observes only the managed drawing source path. NativeSavedChanges debounces two identical file observations, including atomic replacement, and compares saved bytes against the last verified revision. It queues an immutable snapshot with the session ID/path; NativeBridge rejects stale events and writes back through the existing source, conflict, proportion and preview checks. Both save synchronization and the final close export a temporary copy in the pinned ChemDraw application. The managed document is saved in its native format, and its later edits remain intact. Updated previews use distinct content-specific paths inside the Office cache to avoid image-import caching. The final close verifies the drawing, closes the clean editing document and returns to its original Office document.

The event monitor reads process-scoped activity on its independent main run loop and shows a standard AppKit spinning progress indicator beside the system pointer, in a transparent, nonactivating, click-through panel. AppKit supplies its size and appearance. Both success and failure clear activity; parent-process exit removes the indicator. Keyboard input and native dialogs remain usable during synchronization. Close gestures for the original managed window carry the session identity and join the serial transaction queue, so they finish after an in-flight save without affecting a replacement session.

ChemDraw reports an empty drawing through its document object collection. Such a document keeps its native source and uses a positive-sized white SVG canvas instead of requesting an SVG export of missing artwork. Preview verification accepts matching blank canvases and still rejects a blank/nonblank mismatch. The carrier keeps the drawing identity and embedded native source so the blank figure can be reopened.

## Office document lifetime

A one-second timer runs on the existing serial transaction queue while the helper is running. It queries the pinned Office document identity without activation, saving Office or relaunching a quit host. Two consecutive absent observations close an orphaned edit; failed reads, ambiguous identities and document switches retain the editor. Explicit ChemDraw save/close requests check the current target directly and also recover a document closed during rendering or write-back. Cleanup saves only the managed ChemDraw file, closes that exact window without activation, archives the draft and clears monitor state so queued events cannot address it. Failed local saves keep the editor and draft available for retry. Repeated operation errors retain their visible status but raise the setup window only once until successful work or a different error.
